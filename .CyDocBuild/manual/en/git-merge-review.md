# Three-way committed Git review (0.23) {#three-way-committed-git-review-023}

Review changes on both branches since their common ancestor, then request a bounded text
proposal for a selected file. The CLI, native CyUI app, Web console and C/C++ SDK share these
read-only routes. Both interfaces default to English and include French translations.

```sh
cysynck git merge-review PROJECT_ID PEER_ID BRANCH
cysynck git merge-file PROJECT_ID PEER_ID BRANCH 'relative/path.cpp'
```

First import the peer branch through the existing bundle exchange. In the Git exchange view,
open its branch comparison, choose **Review three-way changes**, then **Preview three-way file**.
The proposal, ancestor, local committed version and peer committed version have separate tabs.
Staged and uncommitted edits are excluded and preserved.

## Scope and results {#scope-and-results}

The overview resolves all merge bases. Exactly one common ancestor is required. Unborn local
branches, unrelated histories and multiple merge bases return `can_review:false` with reason
`unborn`, `unrelated` or `multiple_bases`. Shallow and partial-clone/promisor repositories are
refused. SHA-1 and SHA-256 repositories are supported.

The changed-file list is the union of ancestor-to-local and ancestor-to-peer changes. Entries
include `ancestor_info`, `local_info` and `peer_info` with existence, mode, object ID and byte
count. `classification` is `local_only`, `peer_only`, `identical`, `both_changed` or `structural`.
`both_changed` alone does not mean a text conflict. File/directory collisions and case aliases
among the listed paths are marked for structural review. Case checks fold ASCII on POSIX and
use Windows ordinal case comparison on Windows. Unchanged paths elsewhere in the tree are not
checked for collisions. Renames remain deletion/addition pairs.

The selected file returns `texts:{ancestor,local,peer}` when its committed contents are supported,
plus `candidate`, `candidate_mode`, `result_exists`, `clean`, `conflicts`, `kind` and `reason`.

| `kind` | Meaning |
| --- | --- |
| `clean` | A per-file text proposal has no conflict markers generated by this comparison |
| `conflict` | The proposal contains diff3 markers labelled `LOCAL`, `ANCESTOR` and `PEER` |
| `delete` | The three committed versions imply deletion; `result_exists:false` |
| `manual` | The file needs manual Git review; no candidate is returned |

`conflicts` is zero for clean proposals/deletions, null when no proposal was computed, or the
conflict-region count reported by Git, capped at 127. An absent side is an empty string in
`texts`; use its metadata to distinguish absence from an empty file. `candidate_mode` describes
the proposed committed mode; no permissions are applied.

A clean proposal only describes this path. It does not certify that the branches can merge as
a repository, resolve renames, combine multiple merge bases, run tests or validate LFS assets.
Divergent repository integration can use the separate [reviewed merge operation](doc:git-divergent-merge)
from 0.24 when the full repository result is conflict-free. Existing reviewed
[fast-forward integration](doc:git-integration) remains available for eligible histories.

## Bounds and Git attributes {#bounds-and-git-attributes}

Text must be valid UTF-8 without NUL bytes and at most 512 KiB per side. Binary/non-UTF-8 content,
larger blobs, canonical LFS pointers, symlinks, submodules and unsupported file types return
metadata with a manual-review reason. Modify/delete conflicts and ambiguous permission changes
also need manual handling. LFS assets are never hydrated or fetched by these routes.

Committed attributes are checked in all three revisions alongside effective local/global/system
attribute rules. Custom/default merge drivers, binary merge rules and active checkout conversions
(`filter`, `text`, `eol`, `working-tree-encoding`, `ident`, `crlf`) cause manual review. Plain
`merge` is supported; explicitly unset checkout attributes are allowed. No custom driver,
external diff, textconv, hook or fsmonitor command is executed.

For nontrivial supported files, CySynck runs
[`git merge-file`](https://git-scm.com/docs/git-merge-file) with `--stdout`, `--diff3`, explicit
Myers diff selection and fixed labels on three private temporary copies. Git must support
`merge-file --diff-algorithm` and `check-attr --source`; tested locally with Git 2.45.1.
Proposals are bounded below 4 MiB, listings below 8 MiB, and the union is limited to 10,000 paths
of at most 4096 UTF-8 bytes. Git subprocesses have a 120-second timeout.

The source repository's files, index, refs, configuration and object database are preserved.
No merge objects or integration receipts are created. Temporary inputs live under the private
profile at `git-file-previews/RANDOM_ID/` and are removed after success or ordinary failure.
An abrupt process termination can leave private copies there. Cleanup only removes the three
owned input names and their empty directory; it never recursively deletes unexpected content.

## API and stable context {#api-and-stable-context}

The local token-protected API and existing C ABI version 1 expose:

| POST route | Body |
| --- | --- |
| `/api/projects/ID/git-merge-review` | `{"peer":"PEER","branch":"main"}` |
| `/api/projects/ID/git-merge-file` | `{"peer":"PEER","branch":"main","path":"file.cpp","base":"LOCAL_OID","head":"PEER_OID","local_ref":"refs/heads/main","merge_base":"ANCESTOR_OID"}` |

`base` names the current local commit, `head` the imported commit, and `merge_base` the common
ancestor. Pin the overview's values when requesting a file. A changed context is refused;
refs are checked again after reading. Interfaces pin context and discard stale responses.
Detached HEAD uses `local_ref:null` (`--local-ref detached` in the CLI). Requests containing
`apply` or `commit` are rejected. There is no apply action on these routes.
The separate [`git merge` operation](doc:git-divergent-merge) can integrate a reviewed repository
result; from 0.25 it accepts whole-file local/peer choices for supported text conflicts.

```sh
cysynck git merge-file PROJECT_ID PEER_ID BRANCH path.cpp \
  --base LOCAL_OID --head PEER_OID --local-ref refs/heads/main --merge-base ANCESTOR_OID
```
